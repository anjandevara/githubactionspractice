Stage 1 · step 2 of 8

Build the workflow live

aim 0:08–0:25
Voicesay this

"Watch me build it from nothing. I'll type each line and tell you what it means. You do NOT make the folder — GitHub creates it for you the moment you commit."

Handsdo this

Click the Actions tab → set up a workflow yourself. Delete the sample. Rename the file to tests.yml. Type:

name: Tests
on: push
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pytest

Then click the green Commit changes… button → Commit changes.

Screenshow them

Narrate as you type: "name is just a label. on: push is WHEN — every push. jobs → one job called test. runs-on is WHICH machine. steps are WHAT, in order: get the code, install Python, install pytest, run pytest."

"That's the whole file. Five ideas: name, on, jobs, runs-on, steps."

Stage 2 · step 5 of 8

The pull-request gate

aim 0:25–0:38
Voicesay this

"Right now it runs on a push. But the real power is stopping a broken change BEFORE it merges. Let's make it run on pull requests too — and give ourselves a manual button."

Handsdo this — edit the triggers

Actions is done; go to Code → open .github/workflows/tests.yml → click the pencil ✏️. Replace the on: push line with:

on:
  push:
  pull_request:
  workflow_dispatch:

Commit. Now click Actions → Tests → the Run workflow button appeared — that's workflow_dispatch. Click it to run on demand.

Handsdo this — break it on a branch

Go to Code → open src/cart.py → pencil ✏️. Change this one line:

return round(amount * (1 - percent / 100), 2)

to (a real bug — it forgets the discount):

return round(amount, 2)

Under "Commit changes", choose Create a new branch (e.g. fix-discount) → Propose changes → Create pull request.

Screenshow them

On the PR, point at the checks box: "Yellow… now a red ✗. The robot ran our tests on my change and one failed — test_apply_discount_takes_percent_off. GitHub is telling us: don't merge this."

Then fix it: edit the branch's cart.py back to the correct line, commit. Watch the check go green ✓. Merge.

"The test caught my bug automatically — that's the safety net."

Stage 3 · step 6 of 8

Test every version at once

aim 0:38–0:48
Voicesay this

"Our users aren't all on one Python version. Watch us test three at once — from one push."

Handsdo this

Edit tests.yml. Under test:, add a strategy block and swap the fixed version for the matrix value:

    strategy:
      matrix:
        python-version: ["3.10", "3.11", "3.12"]

Change the setup-python python-version: line to:

          python-version: ${{ matrix.python-version }}

Commit. (Full file is stages/v3-matrix.yml if you need it.)

Screenshow them

In Actions, point at the run: "One push — but three jobs, one per version, running in parallel. Each gets its own green tick."

"Coverage across versions for free — you just listed them."

Stage 4 · step 7 of 8

Badge & report

aim 0:48–0:54
Voicesay this

"Two finishing touches testers love: a live badge that proves we're green, and a saved test report you can download."

Handsdo this

Edit tests.yml: change - run: pytest to produce a report and add an upload step:

      - run: pytest --junitxml=report.xml
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: test-report-${{ matrix.python-version }}
          path: report.xml

Commit. Then edit README.md and replace OWNER/REPO in the badge line with your username and repo. Commit.

Screenshow them

Show the README badge going green. In the latest Actions run, scroll to Artifacts and download test-report-3.12. Mention: "You can also run this on a timer with schedule: — e.g. every night."

"Now anyone can see we're green, and every run keeps its receipts."
